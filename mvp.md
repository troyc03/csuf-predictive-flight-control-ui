• 1. Minimum Viable Product (MVP): We are building a Universal Telemetry Ingestion Node & Polymorphic Overlay that accepts a standardized JSON data packet via WebSockets and automatically renders it into a customizable, hardware-accelerated broadcast card. For our immediate client, a lightweight external script will feed LAX flight telemetry into this endpoint to generate zero-touch aviation graphics, but the exact same core pipeline can instantly display car OBD-II metrics or animal tracking data simply by swapping the input data source.
• 2. Absolute Non-Goal: Our software will not build custom hardware drivers or proprietary protocol decoders, meaning we are not writing code to interface directly with Bluetooth OBD-II chips, radio antennas, or GPS collar hardware. Our project scope begins strictly at the network edge; it is entirely up to the user or an external utility script to extract their raw hardware data, format it to match our universal JSON schema, and transmit it to our server.
• 3. Killer Assumption & Test: We assume our single unified data schema can dynamically normalize wildly different data velocities—such as a car sending engine updates 30 times a second versus an animal tracker sending a packet once every 10 minutes—without causing rendering jitter, state-sync lockups, or stream lag. We will test this by running a multi-stream simulation that floods the server with high-frequency, standard-frequency, and slow-trickle mock data streams simultaneously to prove the engine handles variable data loads without leaking memory or dropping frames over an 8-hour stretch.
